# RIDI 스토어 인핸서 (확장 0.5.0)

확장 `0.5.0`은 서재·신간·상세에만 있던 인핸서를 `ridibooks.com` 스토어 전체로 넓힌다.

Steam 확장(Augmented Steam, SteamDB)이 상점 목록에 하는 일 세 가지를 RIDI에 옮겼다.

| Steam 확장의 동작 | RIDI에서의 구현 |
|---|---|
| 보유 게임 강조·숨김 | 서재 색인을 카드에 연결해 소장 배지, 흐리게, 숨김 |
| 무시 목록 | 표지의 `숨김` 버튼과 숨김 목록, 차단어 |
| 무한 스크롤·추가 정보 | 다음 쪽 이어보기, 다른 서점 구매·독서노트 연결 |

## 구성

| 파일 | 역할 |
|---|---|
| `extension/src/store-data.js` | 순수 로직. 페이지 판별, 도서 레코드 정규화, 서재 연결, 표시 규칙, 정렬 |
| `extension/src/store-enhancer.js` | 컨텐츠 스크립트. 카드 수집, 배지·숨김 적용, 툴바, 이어보기 |
| `extension/src/page-enhancer.js` | 서재·신간 인라인 목록과 작품 상세 패널 (기존 파일 확장) |
| `extension/src/page-view.js` | 인라인 목록의 필터·정렬·CSV (기존 파일 확장) |
| `extension/src/page-enhancer.css` | 숨김·흐리게·원본 목록 접기 규칙 |

`store-enhancer.js`는 `https://ridibooks.com/*`에 주입하고 서재·계정·주문·결제·뷰어·독서노트 경로는 `exclude_matches`로 뺀다.

권한은 늘지 않았다.

## RIDI 화면 구조 (2026-11-21 실측)

스토어는 Next.js 페이지 라우터이고 모든 화면이 `__NEXT_DATA__`에 목록 데이터를 싣는다.

| 화면 | 도서 데이터 위치 | 식별 키 | 쪽 넘김 |
|---|---|---|---|
| 카테고리 `/category/{id}` | `dehydratedState.queries[n].state.data[].book` | `bookId`, `serial.serialId` | `?page=N`, 쪽당 60권 |
| 검색 `/search?q=` | `gridData…cells[n].cell__SearchBookListWithTab.books[].book` | `id`, `series.id` | `?page=N`, 쪽당 24권 |
| 베스트셀러 | 카테고리와 같은 형태 | `bookId` | 쪽 번호 링크 없음 |
| 작품 상세 `/books/{id}` | `sectionProps.gridQuery.riGrid.grid.meta.gridPageMeta` | `bookId`, `isbn` | 없음 |

두 목록 형태와 공개 `book-api` 형태를 `normalizeStoreBook`이 한 레코드로 맞춘다.

`extractStoreBookGroups`는 데이터 전체를 훑어 도서 레코드를 배열 단위로 묶고, 가장 큰 묶음을 그 화면의 본문 목록으로 본다.

카테고리 목록은 쪽당 60개 `li`를 미리 깔고 화면에 들어온 것만 채우므로, 카드 장식은 `MutationObserver`로 계속 다시 적용한다.

카테고리 사이드바 이동은 전체 새로고침이고 탭(베스트·신작) 이동은 클라이언트 라우팅이다.

RIDI의 CSP는 외부 출처의 스크립트와 연결을 제한한다. 확장 모듈은 `0.4.0`의 페이지 인핸서와 같은 방식(`web_accessible_resources`의 동적 import)으로 불러온다.

## 카드 판별

카드는 "같은 책만 가리키는 가장 큰 조상"이다.

표지 링크에서 위로 올라가며 다른 책 링크가 섞이거나, 목록(`ul`·`ol`) 경계나 카드 밖 머리말(`h1`–`h3`)을 만나면 멈춘다.

이 규칙으로 카테고리·검색은 `li`, 베스트셀러는 격자 칸 `div`가 카드가 된다.

숨김은 카드 노드에 `data-ridi-driller-vis` 속성을 붙였다 떼는 것으로만 한다.

원본 노드를 지우지 않으므로 React 재렌더와 충돌하지 않고, 설정을 끄면 원래대로 돌아온다.

## 서재 연결

`createStoreLookup`이 서재 색인(`ridi_page_index`)을 카드에 연결한다.

1. 책 ID가 색인에 있으면 `owned`.
2. 시리즈 ID가 색인의 시리즈와 같으면 `ownedSeries`.
3. 정규화한 제목만 같을 때, 카드의 시리즈 ID를 알고 그 값이 색인과 다르면 `otherEdition`이고 소장이 아니다.
4. 카드의 시리즈 ID를 모를 때만 제목 일치를 `ownedSeries`로 본다.

3번은 실화면 검증에서 나온 규칙이다. e북 「원피스」(시리즈 `1019000209`)를 소장한 색인이 연재판 「원피스」(시리즈 `1019015746`)를 소장으로 표시했다.

`__NEXT_DATA__`에 없는 카드(클라이언트 라우팅 뒤의 화면)는 배경 워커가 공개 `book-api`로 책 ID를 최대 100개씩 조회해 시리즈 ID와 성인 여부를 채운다.

이 조회는 서재 색인이 있거나 `성인 숨김`이 켜져 있을 때만 한다.

## 표시 규칙

`cardVisibility`는 규칙마다 `show`·`dim`·`hide`를 내고 가장 강한 것을 고른다.

| 규칙 | 조건 |
|---|---|
| 소장 | `owned` 또는 `ownedSeries`이면서 미구매 권이 없을 때 |
| 완독 | `finished` |
| 숨김 목록 | 책 ID, 시리즈 ID, 정규화 제목 중 하나가 숨김 목록에 있을 때 |
| 차단어 | 제목·시리즈명·작가·출판사에 낱말이 들어 있을 때 |
| 성인 | `isAdult === true` |
| 별점·평가 수 | 값이 있고 기준보다 낮을 때 |

값이 `null`인 항목은 걸러 내지 않는다.

미구매 권이 남은 시리즈는 살 책이 남아 있으므로 `소장 숨김` 대상에서 뺀다.

작품 상세 화면에서는 그 작품의 표지와 같은 시리즈의 권 목록에 표시 규칙을 적용하지 않는다.

## 이어보기

다음 쪽은 현재 주소에 `page`만 바꿔 같은 출처로 요청하고, 응답 HTML의 `__NEXT_DATA__`에서 본문 목록만 꺼낸다.

RIDI의 카드 마크업을 복제하지 않고 확장이 Shadow DOM 안에 자체 카드를 그린다.

원본 목록의 React 노드 사이에 끼워 넣지 않고 목록 바로 뒤에 별도 섹션으로 붙인다.

| 제한 | 값 |
|---|---|
| 쪽 사이 간격 | 0.45초 |
| 자동 불러오기 | 한 번에 10쪽 |
| 한 화면 최대 | 60쪽 |

받은 쪽에 새 책이 없거나 받은 목록이 지금 화면과 같으면 마지막 쪽으로 본다.

불러오는 도중 화면이 바뀌면 결과를 버린다.

## 서재·상세 화면 변경

- 인라인 목록에 유형·완결 필터, 미구매 권수·보유 권수 정렬, 정렬 방향, CSV 저장을 추가했다. Vercel 배포 앱의 `lib/view.ts` 필터·정렬 명세를 따랐다.
- `원본 목록 접기`는 인라인 목록 뒤의 형제 노드를 CSS로 가려 RIDI 원본 목록을 대신한다.
- 작품 상세 패널에 다른 서점 구매 기록(ISBN 일치와 제목 일치를 구분)과 수집한 독서노트 수를 연결했다.
- 작품 상세 패널을 제목이 든 격자 안이 아니라 머리 영역 전체 뒤에 붙인다. 격자 안에 넣으면 한 칸 폭으로 찌그러졌다.
- 표지 링크가 이미 `absolute`로 배치된 화면(베스트셀러)에서 `position: relative`를 덮어쓰지 않는다. 덮어쓰면 카드 높이가 두 배가 됐다.
- CSV는 `=`·`+`·`-`·`@`로 시작하는 칸 앞에 `'`를 붙여 스프레드시트 수식 실행을 막는다.

### 확인하지 못한 것

- 설치된 확장에서의 실행. `manifest.json`의 주입 경로, `chrome.storage.local` 저장, 배경 워커의 `resolveBooks`는 단위 테스트와 코드 검토 범위다.
- 실제 서재 분석 색인(구매 작품 약 1,900개)으로 연결했을 때의 오탐 비율.
- 어두운 테마. 밝기 판별 코드는 있지만 RIDI 웹의 어두운 화면에서 보지 못했다.
- 작가 페이지와 기획전 화면의 쪽 넘김.

## 0.5.0 후속 변경: 목록 하나, RIDI 모양

설치해 본 결과 RIDI 원본 목록 아래위로 확장 목록이 따로 보여 같은 화면에 목록이 둘이었다. 다음과 같이 바꿨다.

| 화면 | 이전 | 지금 |
|---|---|---|
| 구매 목록·책장·관심·만화 신작 | 확장 전체 목록 + 원본 목록이 항상 함께 표시 | 평소에는 원본 목록(배지 덧씌움)과 필터 한 줄. 검색·필터·`전체 보기`를 쓰면 원본을 접고 확장 목록만 표시 |
| 검색·카테고리 이어보기 | 제목이 달린 별도 섹션에 확장 고유의 카드 격자 | 원본 목록 끝에 버튼 하나. 불러온 작품은 원본과 같은 배치로 이어 붙임 |
| 만화 신작의 도구 | 화면 위 막대와 전체 신간 섹션이 떨어져 있고 필터가 겹침 | 막대를 전체 신간 줄 바로 위에 붙이고 겹치는 `골라 보기`는 뺌 |
| 작품 상세 | 작품 서지 패널 + 스토어 막대 | 작품 서지 패널만. 추천 목록은 숨기지 않고 흐리게 |

이어 붙이는 카드는 RIDI 마크업을 복제하지 않는다. 다음 쪽 SSR HTML은 카테고리에서 60개 중 11개만 채워져 있고 검색에서는 표지 이미지가 없어 복제할 수 없었다.

대신 `sampleNativeLook`이 화면의 원본 카드에서 배치(가로 줄/표지 격자), 표지 폭과 위치, 제목·작가·별점·가격의 글꼴 크기·굵기·색을 읽어 확장 카드에 적용한다.

모든 확장 UI의 글꼴은 `font-family: inherit`로 RIDI 화면의 것을 쓰고, 강조색은 RIDI의 파란색(`#1e9eff`)이다.

### 작가·후속권 연결

기존 분석의 "구매 작가의 다른 작품"은 구매 권수 상위 작가 40명만 검색한다. 실제 서재(구매 작품 1,916개, 대표 작가 1,617명)에서 150건이었다.

스토어 카드와 신간 목록은 이제 카드의 작가 ID가 서재 색인의 작가 ID(`catalog[].authorIds`)에 있으면 `구매 작가`로 표시한다. 번역가·삽화가는 제외하고, 이미 소장한 작품과 같은 작품의 다른 판에는 달지 않는다.

작가 ID가 없는 예전 색인은 이름으로 맞추고 배지 설명에 동명이인 가능성을 적는다. 서재를 다시 분석하면 ID로 바뀐다.

읽기 상태 배지는 추천 목록 대신 연결된 서재 기록의 `readingState`를 쓴다. 보유분을 다 읽고 미구매 권만 남은 시리즈가 `안 읽음`으로 표시되던 것이 `보유분 완독`으로 바뀌었다.

| 구매 목록 | 평소 원본 48권만 보이고 확장 목록 0줄. `내 서재 신권 969`를 누르면 원본 0권, 확장 목록 48줄 |
| 만화 신작 | 도구 줄 두 개가 붙어 같은 폭으로 정렬, 원본 격자 하나만 표시 |
| 작품 상세 | 스토어 막대 없음, 숨겨진 추천 카드 0 |

이 Chrome에는 이전 빌드의 확장이 설치돼 있어, 새 코드는 DOM 식별자를 바꿔 따로 주입해 확인했다. 설치된 확장을 새로 고친 뒤의 화면은 아직 보지 못했다.

## 0.5.2: 이어 붙인 줄을 다음 쪽 데이터로 채움

다음 쪽 응답의 HTML에는 완성된 카드가 일부뿐이지만, 같은 응답의 `__NEXT_DATA__`에는 그 쪽 60권 전체의 데이터가 있다. 0.5.1은 이 가운데 제목·작가·별점·권당 가격만 그렸다.

| 항목 | 데이터 위치 | 표시 |
|---|---|---|
| 순위 | 목록 안 자리 | `(쪽 − 1) × 쪽당 개수 + 자리`. 원본 카드에 순위 숫자가 있을 때만 |
| 줄거리 | `book.introduction.description` | 두 줄까지 |

| RIDI 배지 | 목록 항목의 `badges[]` | 문구와 색을 그대로 표지 아래에 |

2쪽 원본 화면의 첫 줄이 `61`로 시작하는 것을 확인해 순위 계산을 맞췄다.

`열 때 합쳐 보기`(`prefetchPages`, 0–4)를 켜면 목록을 처음 그릴 때 다음 쪽들을 불러와 원본 뒤에 합친다. 실화면에서 `3쪽씩`으로 열어 61–180위 120줄이 바로 이어지는 것을 확인했다.

## 0.5.3: 서재·신간 전체 목록을 원본 격자 모양으로

검색·필터를 쓸 때 원본 대신 보이던 전체 목록이 표지 48px짜리 줄 목록이라 RIDI 서재와 모양이 달랐다.

- 전체 목록을 표지 격자로 그린다. `sampleNativeTile`이 원본 표지의 폭·간격·세로 비율을 읽어 같은 칸으로 맞춘다(구매 목록 실측 140×202px, 한 줄 8칸).
- 표지 위에 상태 배지(구매 목록·책장은 `소장` 제외)와 `소장 N/M권`, 아래에 제목·작가·정렬 기준에 맞는 한 줄을 둔다.
- 정렬 기준이나 방향을 바꾸는 것도 전체 목록으로 전환하는 조건에 넣었다. 원본 목록은 서버가 한 쪽씩 주므로 그 안에서만 다시 정렬하면 전체 순서가 아니다.
- 신간 목록에 별점 필터를 넣고, 스토어 막대의 별점 입력을 3.0–5.0의 0.1점 단위 드롭다운으로 바꿨다.

원본 서재 화면이 한 쪽에 내려받는 권수를 늘리는 방식(페이지의 요청을 가로채 `limit`을 바꾸기)은 쓰지 않았다. RIDI 앱의 쪽 계산과 어긋나고, 전체 색인이 이미 모든 쪽의 데이터를 갖고 있다.

실화면에서는 최근 구매 300작품의 색인으로 `미구매 권수순`을 골라 원본 48권이 접히고 격자 48칸이 그 순서로 나오는 것을 확인했다. 이 확인에서는 읽기 기록을 불러오지 않아 읽기 배지는 검증 대상이 아니다.

## 0.5.4: 작가 탭 수정, 정보 중복 제거

- **`구매 작가의 다른 작품` 탭이 열리지 않던 문제.** 탭이 `chrome-extension://…/dashboard.html`로 가는 일반 링크였는데, 웹 페이지에서 확장 페이지로 가는 링크는 `web_accessible_resources`에 없으면 Chrome이 막는다. 탭은 이제 주소에 `#ridi-driller-authors`만 붙이고 그 화면 안에서 분석 결과(`ridi_analysis.authorNew`)를 격자로 보여 준다. `서지 관리` 버튼 세 곳도 같은 이유로 동작하지 않았을 것이라 배경 워커의 `openDashboard`로 열도록 바꿨다.
- **화면 전체에 해당하는 상태를 뺌.** 구매 목록·책장의 `소장`, 관심 작품의 `관심`, 작가 탭의 `구매 작가`. 전부 해당해서 눌러도 달라지지 않는 필터도 숨긴다.
- **한 정보는 한 곳에.** 격자 칸에서 `미구매 N권` 배지·`소장 a/b권` 알약·아래 줄이 같은 내용을 세 번 말하던 것을 알약 하나(`2/64권 · 미구매 62`)로 모았다. 스토어 표지도 `소장 8/9`와 `미구매 1권` 두 배지를 `소장 8/9` 하나로 합쳤고, 이어 붙인 줄 아래의 소장 문구를 없앴다. 작품 상세 패널은 배지 줄과 `시리즈` 줄이 요약 줄을 되풀이하던 것을 요약 한 줄로 줄였다.
- **배지 모양.** 원색 블록 대신 어두운 반투명 바탕에 상태 색 점을 찍은 작은 칩으로 통일했다.

실화면(최근 구매 300작품 색인)에서 탭을 실제로 눌러 주소가 `/library/books#…`로 바뀌고 원본 48권이 접힌 채 16칸 격자가 나오는 것, 구매 목록의 필터에서 `소장 300`이 사라지고 원본 표지 배지가 `완독`·`미구매 권`·`안 읽음`만 남는 것을 확인했다. 관심 작품 화면과 작품 상세 패널의 바뀐 모습은 실화면에서 보지 못했다.

## 0.5.5: 검색 고도화

`dashboard-admin-harness` 스킬의 규칙 가운데 로컬 색인 검색에 해당하는 것만 골라 적용했다. 이 스킬은 서버가 있는 관리자 화면을 전제로 하므로 나머지는 범위 밖이다.

| 규칙 | 적용 |
|---|---|
| Q01 검색 범위와 일치 방식 | 통합 검색과 항목별 검색(`작가:` 등)을 구분. 부분 일치, NFKC·대소문자·공백 무시를 명시 |
| Q02 조건 조합과 제외 | 띄어쓰기 AND, `\|` OR, `-` 제외, 따옴표 묶음. 해석 결과를 조건 칩으로 보여 주고 하나씩 지움 |
| Q03 전체 결과에 적용 | 검색·필터·정렬을 쪽을 나누기 전 전체 색인에 적용(기존). 정렬 동률을 고유 키로 가름 |
| Q04 상태 복원 | 검색어·필터·정렬을 화면별로 `chrome.storage.local`에 저장(기존) |
| Q05 조회 제한 | 낱말 12개·OR 묶음 4개·낱말 길이 60자로 제한, 입력 150ms 뒤 반영 |
| U03 검색 결과 없음 | 걸린 조건, 문법 안내, `조건 모두 지우기` |

적용하지 않은 것: 서버 권한·SQL 매개변수·감사 기록·내보내기 권한(서버 없음), 10·30·50·100개 쪽 크기와 5쪽 이동(표지 격자에는 24·48·96이 맞음), 공유 URL(로컬 데이터라 대상 없음), 검증 기록 `report.json`(요청 범위가 기능 선별이라 만들지 않음).

구현은 `extension/src/search-query.js` 한 곳에 두고 인라인 목록(`page-view.js`)과 서지 관리(`dashboard.js`)가 함께 쓴다. 이전에는 두 곳 모두 "공백을 지운 한 덩어리 부분 일치"라 `오다 원피스`처럼 순서가 다르면 찾지 못했다.

실화면(최근 구매 300작품)에서 `출판사:…`로 38개, 여기에 `-작가:…`를 더해 37개, 없는 낱말로 0개와 빈 상태 안내가 나오는 것을 확인했다. 서지 관리 화면의 검색은 같은 모듈을 쓰지만 실화면에서 보지 못했다.

## 0.5.6: 결과를 원본 목록 자리에, 분석 진척률

- **결과 영역 분리.** 검색·필터 결과가 도구 줄과 같은 상자 안에 그려져, 아래의 원본 목록이 사라지고 위쪽 새 영역에 내용이 생기는 것처럼 보였다. 결과는 이제 별도 요소(`#ridi-driller-results`)로 원본 목록 바로 앞, 같은 부모 안에 놓는다. 켜지면 원본 목록과 그 뒤의 쪽 번호에 `data-ridi-driller-native="hidden"`을 붙여 가리고, 꺼지면 속성을 뗀다.
- **같은 칸.** 원본 목록에서 칸의 폭·높이, 표지의 크기와 칸 안 위치, 줄·칸 간격, 정렬, 안쪽 여백을 읽어 결과 격자에 그대로 쓴다. 구매 목록 실측에서 원본 첫 표지와 결과 첫 표지가 같은 x(105px)·같은 크기(140×199px)였다.
- **바탕 제거.** 도구 줄과 결과에 흰 상자 바탕을 두지 않아 RIDI 목록의 일부로 보인다. 건수는 도구 줄 머리에 적어 결과 위에 줄이 더 생기지 않게 했다.
- **분석 진척률.** 배경 워커가 보내는 단계(`library`·`enrich`·`reading`·`authors`·`interest`)와 처리 건수로 퍼센트를 계산한다. 다섯 단계를 같은 비중으로 보고 단계 안에서는 건수 비율을 더한다. 완료 전에는 99%를 넘기지 않는다. 진척 메시지는 자주 오므로 화면 전체를 다시 그리지 않고 막대와 문구만 고친다.

진척률은 단계별 소요 시간이 아니라 단계 수 기준이라, 요청이 가장 많은 읽기 상태 단계에서 실제보다 빨리 올라가거나 느리게 보일 수 있다.

실화면에서 필터를 눌러 결과가 원본 목록 자리에 같은 표지 크기로 나오는 것과, 진척 메시지를 넣었을 때 `서재 분석 51% · 3/5단계 · 읽기 894/1687`과 51% 막대가 표시되는 것을 확인했다. 진척 메시지는 실제 분석이 아니라 같은 형식의 메시지를 직접 넣어 확인했다.

## 0.5.7: 작가 탭을 RIDI 탭 모양으로

`구매 작가의 다른 작품` 탭은 RIDI 탭 링크를 얕게 복제해 밑줄 막대(`span`)가 없었고, 선택 표시를 굵은 글씨로만 흉내 냈다. 그래서 탭을 골라도 `구매 목록`의 밑줄이 남아 두 탭이 함께 선택된 것처럼 보였다.

- 탭을 막대까지 깊게 복제한다.
- 선택/비선택 모양은 RIDI 탭의 class 쌍(링크, 막대)을 화면에서 읽어 그대로 쓴다. 고르면 선택 모양을 이 탭으로 옮기고 원래 선택돼 있던 RIDI 탭은 비선택 모양으로 바꾼다. RIDI 탭을 누르거나 뒤로 가면 되돌린다.
- 작가 탭에서는 구매 목록 전용 도구 줄(`nav`: 모든 책 검색·편집)을 가린다.
- 도구 줄의 제목에서 탭 이름을 되풀이하지 않고, 고를 필터가 없으면 필터 줄을 두지 않는다.

실화면에서 탭을 눌렀을 때 이 탭이 `tabButtonToggle` class·굵은 글씨·회색 밑줄이 되고 `구매 목록`이 비선택으로 바뀌는 것, `구매 목록`을 다시 누르면 선택 표시·도구 줄·원본 48권이 모두 돌아오는 것을 확인했다.

## 0.6.0: RIDI 목록 자체를 거르기, 원래 필터 복원

### 구매 목록 다리 (`library-bridge.js`)

서재 앱은 쪽을 바꿀 때마다 XHR로 `library-api…/items/main/`(목록)과 `…/items/main/count/`(건수)를 받고, 받은 책 ID로 `book-api` 등을 스스로 부른다.

`library-bridge.js`는 페이지 세계(`world: "MAIN"`, `document_start`)에서 `XMLHttpRequest.prototype.open`을 감싸 이 두 요청에만 처리기를 단다. 응답이 200으로 끝나면 `responseText`·`response`를 걸러진 목록의 해당 구간과 걸러진 건수로 바꾼다. 나머지는 RIDI가 한다.

| 문제 | 해결 |
|---|---|
| 걸러진 결과를 페이지 세계에 넘기기 | 컨텐츠 스크립트가 `sessionStorage`의 `ridi-driller:library-view`에 원본 목록 항목 배열을 적는다. 두 세계가 같은 저장소를 보므로 새로고침 직후 첫 요청부터 적용된다 |
| 필터를 바꿨을 때 다시 받게 하기 | 서재 앱은 쪽 번호가 바뀔 때마다 새로 요청한다(캐시 없음, 실측). `history.replaceState`와 `popstate`로 2쪽에 80ms 들렀다 1쪽으로 돌아온다. 그동안 목록을 흐리게 한다 |
| 쪽 번호 | 건수 응답을 걸러진 건수로 바꾸므로 RIDI가 쪽 수를 다시 계산한다. 필터를 바꾸면 항상 1쪽으로 간다 |
| 걸러진 뒤 RIDI가 또 받는 것 | 목록의 책 ID로 표지·열람 정보를 받는 요청은 RIDI가 평소대로 보낸다. 손대지 않는다 |
| 확장 자신의 화면 갱신 | 쪽 번호만 바뀐 것은 같은 화면으로 본다. 그렇지 않으면 재조회 때마다 도구 줄이 다시 그려져 입력 중인 검색어가 날아간다 |
| 실패 | 저장된 값이 없거나 깨졌거나, 응답이 200이 아니거나, 모르는 조건이 붙은 요청이면 원본 응답이 그대로 쓰인다 |

원본 목록 항목은 서재 분석이 `ridi_library_units`에 저장한다. 없으면 다리를 쓰지 않고 확장이 원본 자리에 직접 그린다.

실화면(최근 구매 300작품)에서 `내 서재 신권`을 눌렀을 때 RIDI 목록이 걸러진 125작품의 앞 48권을 예상 순서대로 보여 주고, 쪽 번호가 1·2·3으로 줄고, 확장의 결과 영역은 숨겨진 것을 확인했다. 이 확인은 다리 스크립트를 앱이 뜬 뒤에 넣어서 한 것이다. 설치된 확장에서 `document_start`에 먼저 들어가는지는 보지 못했다.

### 원래 웹 앱에 있던 필터

웹 앱(`lib/view.ts`)의 필터 가운데 확장에 없던 것은 서지 레코드에 그 값이 없었기 때문이다.

| 필터 | 빠져 있던 이유 | 복원 |
|---|---|---|
| 성인 전체·만·제외, 잡지 제외 | 서지에 `isAdult`·`isMagazine`을 넣지 않음 | 책 정보의 `is_adult_only`·`is_magazine`을 서지에 기록 |
| 카테고리 | 값은 있었으나 고르는 곳이 없음 | 드롭다운 |
| 별점 슬라이더, 별점순, 태그 | 웹 앱은 분석의 `ratings` 단계에서 제목 검색으로 별점·태그를 찾아 저장하고 합쳤는데, 확장으로 옮기며 그 단계가 빠짐 | 분석에 `ratings` 단계 복원. `ridi_ratings`에 저장하고 서지에 합침 |
| 더 보기·무한 스크롤 | 쪽 번호만 구현 | 넘기는 방식 선택 |

별점 조회에서 검색 결과에는 시리즈 ID 칸이 없고 시리즈는 대표 책 ID로 나온다는 것을 확인했다. 결과의 책 ID가 작품의 시리즈 ID나 책 ID와 같은 것만 쓴다. 이 기준으로 실제 40작품 중 40개가 ID로 일치했다(책 ID 17, 시리즈 ID 23). 웹 앱은 일치하는 것이 없으면 첫 번째 검색 결과를 썼는데, 그 대체는 넣지 않았다.

같은 이유로 `구매 작가의 다른 작품`에서 보유 시리즈를 빼는 조건도 `series_id`가 아니라 책 ID로 비교하도록 고쳤다.

### 드롭다운

`dashboard-admin-harness`의 U02(입력 컴포넌트)·U04(접근성)에 맞춰 서재 도구 줄과 스토어 막대의 `select`를 하나의 `dropdown()` 구성으로 통일했다.

- 레이블을 화면에 보이게 붙인다(`유형 | 전체`). 이전에는 `aria-label`뿐이라 값을 고르면 무엇의 값인지 보이지 않았다.
- 기본값이 아닌 값을 고르면 `data-active`로 테두리·바탕·굵기를 바꾼다. 눌린 필터 칩과 같은 표현이다.
- 포커스는 2px 테두리, 비활성은 흐리게와 금지 커서로 구분한다.
- 강조 글씨색을 `#1e9eff`(흰 바탕 대비 약 3:1)에서 `#0b6bcb`(약 5:1)로, 보조 글씨색을 `#787878`에서 `#6b6b6b`로 바꿨다. 채운 버튼의 바탕도 같은 색으로 맞췄다.
- 확장 컨텐츠 스크립트는 페이지에 끼어 들어가는 구조라 shadcn 같은 컴포넌트 라이브러리를 싣지 않고, 네이티브 `select`(키보드·화면 낭독기 동작이 기본 제공됨) 위에 모양만 입혔다.

실화면에서 `성인 제외`를 골랐을 때 그 드롭다운만 파란 테두리·굵은 글씨가 되고, RIDI 목록이 성인 작품을 뺀 239작품으로 바뀌는 것을 확인했다.

## 0.6.1: 설치 안내 모달, 진척률이 페이지에 오지 않던 문제

### 설치 안내 모달 (`onboarding.js`)

서재 분석 결과가 없고 안내를 닫은 적이 없을 때 RIDI 화면에 한 번 띄운다. 네이티브 `<dialog>`의 `showModal()`을 써서 포커스 가두기, Esc 닫기, 닫은 뒤 포커스 복귀를 브라우저에 맡긴다.

- `서재 분석 시작`을 누르면 창 안에서 진척률을 보여 주고, 끝나면 닫기 버튼만 남는다.
- `나중에`·Esc로 닫으면 `ridi_onboarding_dismissed`를 기록해 다시 띄우지 않는다. 분석 중에 `숨기기`를 눌러도 분석은 계속된다.
- 로그인돼 있지 않으면 시작 버튼을 막고 로그인 링크를 보여 준다.
- 설치 직후(`onInstalled`의 `install`)에 구매 목록 탭을 열어 이 창이 바로 보이게 한다. 업데이트 때는 열지 않는다.
- 서재 화면과 스토어 화면의 스크립트가 모두 부르지만 창은 하나만 뜬다.

### 진척률 전달

배경 워커의 `broadcast()`는 `chrome.runtime.sendMessage`만 썼다. 이 호출은 팝업·서지 관리 같은 확장 자신의 화면에만 닿고 RIDI 페이지의 컨텐츠 스크립트에는 닿지 않는다. 그래서 페이지에는 `전체 서재를 다시 분석하는 중`이라는 고정 문구만 보이고 진척률이 한 번도 오지 않았다.

- `broadcast()`가 RIDI 탭을 찾아 `chrome.tabs.sendMessage`로도 보낸다. 건수마다 오는 진척 메시지는 0.2초에 한 번으로 줄이고, 단계의 시작·끝·완료·오류는 항상 보낸다.
- `서재 다시 분석`을 누르면 첫 메시지를 기다리지 않고 바로 `서재 분석 0% · 1/6단계 · 서재 목록 불러오는 중…`을 띄운다.
- `running` 응답에 마지막 진척 상태를 실어, 분석 도중에 연 화면도 이어서 표시한다.
- 문구는 제목 옆 상태 글에 적고 막대 옆에는 되풀이하지 않는다.

이전 버전(0.5.6)의 진척률 확인은 메시지를 페이지에 직접 넣어서 한 것이라 이 전달 문제를 드러내지 못했다. 이번 수정도 설치된 확장에서 실제 분석을 돌려 확인하지는 못했다. 탭으로 보내는 경로는 코드와 테스트 범위다.
