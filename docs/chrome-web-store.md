# 북드릴 Chrome 웹 스토어 등록 안내

확장 이름은 `북드릴`, 등록할 파일은 `public/ridi-driller-extension.zip`(버전 `0.7.1`)이다.

등록 자체(개발자 계정 생성, 등록비 결제, 제출)는 Google 계정 주인이 직접 해야 한다. 이 문서는 그때 붙여 넣을 내용과 심사에서 걸릴 수 있는 점을 정리한 것이다.

## 절차

1. [개발자 등록](https://developer.chrome.com/docs/webstore/register): Chrome 웹 스토어 개발자 대시보드에서 등록하고 일회성 등록비를 낸다. 2026년 4월 Chrome 블로그는 5달러라고 적었다. 결제 전에 등록 화면의 금액을 확인한다.
2. Google 계정에 2단계 인증을 켠다. 켜지 않으면 게시할 수 없다.
3. 대시보드에서 `새 항목`을 누르고 `public/ridi-driller-extension.zip`을 올린다.
4. 아래 "스토어 등록 정보"와 "개인정보 탭"을 채운다.
5. `검토를 위해 제출`을 누른다. 승인 뒤 30일 안에 게시해야 한다.

새 게시자는 게시할 수 있는 확장 수에 제한이 있다(처음에는 2개, 이후 게시자별로 조정).

출처: [게시 안내](https://developer.chrome.com/docs/webstore/publish), [2026년 심사 변경 사항](https://developer.chrome.com/blog/cws-review-updates-2026), [프로그램 정책](https://developer.chrome.com/docs/webstore/program-policies/policies)

### 이미지

| 항목 | 규격 | 상태 |
|---|---|---|
| 아이콘 | 128×128 PNG | `extension/icons/icon128.png` 있음. RIDI 로고를 닮지 않았는지 확인 |
| 스크린샷 | 1280×800 또는 640×400, 1–5장 | **직접 찍어야 함** |
| 작은 홍보 타일 | 440×280 | **만들어야 함** |

이미지 규격은 이전에 알던 값이다. 대시보드의 업로드 화면에 적힌 값을 따른다.

스크린샷에는 성인 표지가 들어가면 안 된다. 성인 작품이 없는 카테고리 화면이나 `성인 숨김`을 켠 상태에서 찍는다. 개인 구매 내역이 드러나지 않게 한다.

## 개인정보 탭

### 단일 목적

```
RIDI 전자책 서재를 관리하기 위한 확장입니다. 사용자의 RIDI 서재를 브라우저 안에서 분석해 RIDI 화면에 소장·읽기 상태를 표시하고 목록을 검색·필터·정렬합니다.
```

### 권한 사유

| 권한 | 사유 (붙여 넣기용) |
|---|---|
| `storage` | 서재 분석 결과, 필터 설정, 사용자가 숨긴 작품 목록을 사용자의 브라우저에 저장합니다. |
| `cookies` | 사용자가 RIDI에 로그인돼 있는지 확인합니다. 쿠키 값을 저장하거나 전송하지 않습니다. |
| `activeTab`, `scripting` | 사용자가 다른 서점의 구매내역 화면에서 확장 버튼을 눌렀을 때에만, 그 화면에 보이는 구매 기록을 읽어 서재에 합칩니다. |
| 호스트 권한 `ridibooks.com` | RIDI 화면에 배지와 필터를 표시하고, 사용자의 서재 목록·읽기 기록·작품 정보를 RIDI에서 읽어 옵니다. |
| 원격 코드 | 사용하지 않습니다. 모든 코드는 패키지에 들어 있습니다. |

### 데이터 사용

- 외부로 전송하는 데이터는 없다. 개발자 서버가 없다.
- 양식의 수집 항목은 "웹사이트 콘텐츠"(서재 목록·읽기 기록)와 "사용자 활동"에 해당할 수 있다. 기기 안에서만 처리해도 "수집"으로 볼지는 양식의 문구를 보고 정한다. 판단이 어려우면 표시하고 "기기 안에서만 처리, 전송 없음"이라고 설명에 적는 쪽이 안전하다.
- "판매하지 않음", "단일 목적과 무관한 용도로 쓰지 않음", "신용 평가에 쓰지 않음" 세 가지 확인란은 모두 해당한다.

## 심사에서 걸릴 수 있는 점

| 위험 | 내용 | 대응 |
|---|---|---|
| 상표 | 이름·아이콘·스크린샷이 RIDI의 공식 제품처럼 보이면 반려될 수 있음 | 이름을 `북드릴`로 바꿈. 설명에 "RIDI와 제휴·공식 아님"을 넣음. 아이콘 확인 필요 |
| 단일 목적 | 다른 서점(알라딘·YES24·교보·영풍) 구매 기록 가져오기가 별개 기능으로 보일 수 있음 | "전자책·도서 서재 관리"로 묶어 설명. 반려되면 스토어용 빌드에서 이 기능과 `activeTab`·`scripting` 권한을 뺌 |
| 권한 최소화 | `cookies`는 로그인 확인에만 씀 | 사유를 위 표대로 적음. 문제 삼으면 권한을 빼고 API 응답(401)으로 로그인 여부를 판단하도록 바꿀 수 있음 |
| 페이지 요청 변경 | 구매 목록에서 RIDI 서재가 받는 응답을 바꿈(`library-bridge.js`) | 설명과 개인정보 처리방침에 적음. 읽기 요청 두 개만 다루고 실패하면 원본이 쓰임 |
| RIDI 약관 | 서재 분석은 사용자의 세션으로 RIDI에 수천 건의 조회를 보냄. RIDI가 자동화된 접근을 금지하거나 스토어에 삭제를 요청할 수 있음 | 스토어 정책 위반은 아니지만 RIDI의 이용약관을 확인. 요청 간격·동시 수는 코드에서 제한 중 |
| 성인 콘텐츠 | 스토어 이미지에 성인 표지가 보이면 반려 | 위 스크린샷 주의 사항 |
| 개인정보 불일치 | 개인정보 탭, 처리방침, 실제 동작이 다르면 삭제될 수 있음 | 세 곳의 내용을 같게 유지. 기능을 바꾸면 `public/privacy.html`도 함께 고침 |

## 이후 업데이트

처음 한 번은 대시보드에서 직접 올린다. 그 뒤에는 [Chrome 웹 스토어 API](https://developer.chrome.com/docs/webstore/using-api)로 올리기와 게시를 자동화할 수 있다. OAuth 클라이언트와 확장 ID가 필요하므로 첫 게시 뒤에 설정한다.

업데이트할 때마다 `extension/manifest.json`의 `version`을 올리고 `npm run extension:package`로 ZIP을 다시 만든다.
